# 0xui — Plan

0xui is a shadcn-style registry of web3 React components built on **wagmi v3 + viem v2 + ui-sdk + Tailwind v4**, with docs on Astro Starlight. You install components with `shadcn add`, and the source is copied into your app.

**North star:** the web3 component library with the best DX and the best support for agents. Every component installs with one command, compiles on the first try, exposes its state as named types, and can be used either headless (hook only) or styled.

## 2. Architecture conventions (apply to every component)

These come from the chain-selector refactor. They are what make the library predictable for humans and agents.

### 2.1 Three layers per component

1. **Hook**: `useChainSwitcher`, `useConnectWallet`, `useTxFlow`… It holds all wagmi calls and state, and is **exported** so people can build their own UI on it.
2. **Parts**: small presentational pieces (rows, triggers, lists) that take plain props.
3. **Shell(s)**: the default composed component. Variants (popover / dialog / drawer) are thin shells over the same hook and parts and never fork the logic.

**Since the 2026-11-24 rebuild**, the logic under the hook is framework-free:

- `registry/default/lib/*.ts` holds controllers on `@wagmi/core` and viem, over a tiny store (`@0xui/0xui-store`). No React, wagmi React or ui-sdk React imports; `lib/framework-free.test.ts` checks it.
- The React hook is thin: it reads the store with `@0xui/use-store`. A Vue or Svelte port replaces only the hook and the markup.
- UI behavior (keyboard, focus, ARIA, overlays) comes from ui-sdk through 0xui's styled primitives in `components/primitives/*`. The responsive dialog's drawer is the ui-sdk Dialog with `presentation="sheet"`.

### 2.2 Prop contract

- `variant`, `size`, `className` on the root.
- Icon slots accept `ComponentType<…> | false`. `false` hides the icon. There is a global `disableIcons`.
- Overlays are controlled and uncontrolled: `open` / `defaultOpen` / `onOpenChange`.
- Callbacks are named `onX` (`onConnect`, `onSuccess`, `onError`) and receive typed payloads.
- JSDoc on every public prop. This is mandatory because agents read it.

### 2.3 State is a named union, exported

```ts
export type TxPhase = "idle" | "confirming" | "pending" | "success" | "error";
export type ConnectPhase = "idle" | "connecting" | "connected" | "error";
```

Components also set `data-phase={phase}` on the root, so CSS and tests can target each state without reading internals.

### 2.4 Web3 correctness rules

- Amounts are `bigint` from end to end. Format with viem `formatUnits` / `parseUnits`. Never use `Number()` or `parseFloat` on token amounts.
- Amount inputs use `type="text" inputMode="decimal"` with string state, never `type="number"`.
- Addresses are shown as checksummed, then truncated (`0x1234…abcd`), and always copyable.
- Explorer links come from `chain.blockExplorers.default.url`. No hardcoded explorers.
- Wallet rejection (`UserRejectedRequestError`) is its own quiet state ("Request cancelled"), not a red error.
- SSR safety: components render a stable placeholder until mounted. They never render wallet state on the server.

### 2.5 Accessibility and UX baseline

- Hit targets are at least 44px. Every list supports keyboard navigation. Icon-only triggers carry `aria-label`.
- Live phase changes go to an `aria-live="polite"` region. Errors use `role="alert"`.
- Every spinner has a label. Disabled CTAs name what is blocking them ("Insufficient balance"), not just "Disabled".
- Light and dark mode use CSS variables only.

### 2.6 Shared registry libs

Components depend on these through `registryDependencies` instead of duplicating code:

| Item           | Type            | Contents                                                                                                                                                                             |
| -------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `0xui-utils`   | `registry:lib`  | `truncateAddress`, `formatTokenAmount` (compact, fixed decimals), `parseAmount` (lenient: `.5`, `1,000`, pasted `$`), `getExplorerUrl(chain, {tx\|address})`, `isUserRejection(err)` |
| `use-mounted`  | `registry:hook` | SSR mount guard, extracted from chain-selector                                                                                                                                       |
| `use-copy`     | `registry:hook` | Clipboard plus a "copied" state with a timeout                                                                                                                                       |
| `wagmi-config` | `registry:file` | Starter config with `injected()` and commented-out `walletConnect` / `coinbaseWallet`, plus an `ssr: true` note                                                                      |

### 2.7 Definition of done (per component PR)

- [ ] Registry item with complete `dependencies` and `registryDependencies`. `shadcn add` into a fresh Vite app compiles.
- [ ] `description` written like a search snippet: what it does, which states it handles, which hooks it wraps.
- [ ] Hook, parts and shell are exported. Phase type is exported.
- [ ] Docs page with a live demo for **every phase**, an install command, a props table, "when to use" and a minimal copyable example.
- [ ] Vitest tests against the wagmi `mock` connector covering the happy path, rejection and error.
- [ ] Keyboard and screen reader pass.

Each phase ends with something shippable: components live on the docs site and installable from `/r/*.json`.

- Demo config: add the wagmi `mock` connector (fixed accounts, so docs demos work with no wallet installed) and `injected()`. Add a shared `<Demo>` provider wrapper and drop the per-component `*-with-provider.tsx` / `*-wrapper.astro` duplication.
- Add `0xui-utils`, `use-mounted` and `use-copy` as registry items. Move chain-selector onto them.
- Upgrade `wagmi-config` (connectors, ssr note).
- Rewrite `README.md`. Remove the example guide pages and `test-wagmi.mdx`. Sidebar sections: **Getting started** (installation, wagmi setup, conventions) and **Components**.
- Set up Vitest + Testing Library + a mock-connector test util. Add a first test for chain-selector.
- CI (GitHub Actions): `lint`, `check`, `test`, `build`, `registry:build`, plus a smoke job that runs `shadcn add` of every item into a fresh Vite app and runs `tsc`.

**Phase 0 follow-ups**

- **Registry domain.** The docs live at `https://0xui.io`, set in the docs, README, registry and Astro `site`. Later, list `@0xui` in the shadcn registry index so users don't need the `components.json` entry.
- **`@web3icons/react/dynamic` emits about 2k lazy chunks** (every token and network icon) in a consumer's build. They are never loaded unless used, but they slow builds and add noise. Consider a static per-chain import map.
- **Radix**: dropped 2026-11-18, back since the 2026-11-24 rebuild: components use 0xui's ui-sdk primitives, so the shadcn flavor no longer matters. The Radix smoke job is still gone.
- **Docs demos share one wagmi config**, so switching chain in one demo moves every demo on the page. Fine for now. Give each island its own config if it starts to confuse.
- `wagmi-config` is **not** a `registryDependency` of components. Components only need some `WagmiProvider` above them, and forcing the file in would clash with existing setups.

### Phase 1: Easy primitives ✅ done 2026-10-11

`copy-button` → `explorer-link` → `address` → `avatar` → `chain-badge` → `token-icon` → `token-amount` → `block-number` → `gas-price`.
These are fast and they lock in the conventions before the big components.

**Phase 1 notes**

- `avatar` shipped as **`address-avatar`** (`AddressAvatar`) to avoid clashing with the shadcn `avatar` primitive.
- `ChainIcon` now lives in `chain-badge`, and `chain-selector` and `token-icon` depend on it.
- `token-icon` has no lookup by contract address. Pass `src` (token-list `logoURI`) instead. Mapping addresses would mean shipping the whole web3icons token metadata.
- `Web3Provider` takes an optional `queryClient`. Tests use it to turn off retries, and apps can reuse their own client.
- The test RPC is fake: `createTestConfig({ rpc: { eth_blockNumber: "0x…" } })`. Any method that isn't mocked fails, so tests never touch the network.

### Phase 2: Must-haves ✅ done 2026-10-11

`connect-wallet` → `account` → `wallet-button` → `balance` → `transaction-button` → `transaction-status` → chain-selector follow-ups.
**Milestone:** a "Hello dapp" guide that connects, shows the account, switches chain and sends a tx using only 0xui components. ✅ `getting-started/hello-dapp`.

**Phase 2 notes**

- **Receipts:** wagmi's `useWaitForTransactionReceipt` _throws_ on a reverted transaction and drops the receipt. `transaction-status` exports `useMinedReceipt`, which waits with viem directly, so reverted transactions come back as data. `transaction-button` uses it too.
- **Wrong network:** `transaction-button` doesn't switch and send in one click. On the wrong network the label is "Switch to X" and clicking only switches. Two wallet prompts from one click would surprise people.
- **Simulation:** added 2026-11-18 as the `simulate` prop (see "Planned features" below). Use `disabledReason` for blockers the form already knows.
- **Mobile:** added 2026-11-18 as `responsive-dialog` (see "Planned features" below).
- **Docs demos:** the Demo Wallet simulates transactions. `eth_sendTransaction` returns a fake hash, and the demo transport serves its receipt about 3 s later. Sending to `0x…dEaD` reverts. Nothing is broadcast.
- **Tests:** `fakeChainRpc()` in `test/wagmi.tsx` is a chain that advances a block on each poll and mines sent transactions. Test configs drop Multicall3 (so reads are plain RPC calls) and have no storage (so the chain and recent wallet don't leak between tests).

### Phase 3: Good to have ✅ done 2026-10-11

`amount-input` → `token-select` → `token-input` → `address-input` → `approve-button` → `network-guard` → `sign-message` → `transaction-toast` → `add-token`.

**Phase 3 notes**

- **`address-input` callbacks:** `onValueChange(text)` fires on every keystroke and `onResolve(state)` fires when validation settles. One callback can't carry both, because ENS resolution is async.
- **Approvals:** `approve-button` approves the exact amount by default. `unlimited` is opt-in. The USDT approve-0-first quirk is handled since 2026-11-18 (`resetFirst`).
- **Toasts:** `transaction-toast` adds the shadcn `sonner` primitive, which pulls in `next-themes`. Since 2026-11-24 it uses `@0xui/primitive-toast` (ui-sdk Toast) instead; apps mount its `Toaster`.
- **Repo setup:** `tsconfig` `@/*` now lists `src/` before `registry/default/`. A path exists in only one of them, so resolution is unaffected, but `shadcn add <primitive>` now writes into `src/`.
- **Demo Wallet:** signs with a throwaway key, so its signatures don't verify against the demo address. It also remembers demo approvals. The docs config sets `batch.multicall: false` so allowance reads can be intercepted.
- **Test helpers:** `erc20CallRpc()` and `ensResolveRpc()` in `test/wagmi.tsx`, plus custom `accounts` in `createTestConfig`, so signatures can verify with a real key.

### Phase 4: Nice to have ✅ done 2026-10-11

`send` → `swap` → `batch-transaction` → `contract-form` → `portfolio` → `transaction-history` → `ens-profile` → `nft-card` → `event-feed`.

**Phase 4 notes**

- **Blocks:** `send`, `swap` and `portfolio` are `registry:block` items with their own "Blocks" docs section.
- **Swap quotes:** `swap` takes `getQuote` and has no built-in aggregator. Quotes are debounced (400 ms), cached per amount, and refreshed every 15 s.
- **Button labels:** `transaction-button` now lets in-flight and success phases override `disabledReason`, so forms that clear on success still show "Done".
- **Batch transactions:** `batch-transaction` picks atomic via `useCapabilities` (`atomic.status` supported/ready). Sequential mode stops at the first revert or cancel, and the docs warn that it isn't all-or-nothing.
- **History storage:** `transaction-history` uses a module-level store with localStorage and `useSyncExternalStore`, synced across tabs and capped at 50 entries. It's per device: cross-device history needs an indexer.
- **NFT states:** `nft-card` separates `not-found` from `metadata-error`. Public IPFS gateways returned 429 during testing, so production apps should pass their own `gateway`.
- **Demo Wallet:** supports EIP-5792 (atomic everywhere) and stays connected across docs pages (persisted flag, since the mock only remembers in memory).
- **Remaining follow-ups:** the real registry domain. The mobile drawer and `simulate` shipped 2026-11-18.

### Token lists (2026-10-11)

- Every token-taking component uses the **token list standard** (tokenlists.org, Uniswap's format). `Token` is `TokenInfo` from `@0xui/token-list`: `tags`, `extensions` and `bridgeInfo` included.
- **`@0xui/token-list` lib:** types, `parseTokenList` (validates, drops non-EVM entries such as Uniswap's Solana tokens, checksums addresses), `fetchTokenList` (http/ipfs/ar), `mergeTokenLists`, `nativeToken(chain)` and `UNISWAP_DEFAULT_LIST`.
- **`@0xui/use-token-list` hook:** multiple lists, chain filter, native currency first, `extraTokens`, cached per session.
- **Docs:** demos load Uniswap's default list live (about 1,800 tokens, 412 on Ethereum including ETH).
- **Big lists:**
  - `TokenSelect` shows 100 rows until you search and has a loading state.
  - Held tokens sort by value when `prices` is given, otherwise in list order. Raw amounts aren't comparable: an airdropped 15bn-token balance used to top the list.
  - `TokenIcon` resolves `ipfs://` logos and only mounts the built-in icon after the list logo fails. Mounting it as a placeholder fetched a built-in icon for every row.
- **Demo Wallet:** Multicall is back on in the docs config, and the demo transport patches allowance results inside Multicall3 `aggregate3` batches.

### Filters, pagination, indexed data (2026-10-12)

- **Filters:** `applyTokenFilters` and `useTokenList({ allowlist, blocklist })` take addresses or `chainId:address`. Symbols aren't accepted, because spam copies them. The blocklist wins, and the native currency is always kept.
- **Pagination:**
  - `TokenSelect`: `pageSize` (50), infinite scroll via IntersectionObserver, plus a "Show more" button.
  - `Portfolio` and `TransactionHistory`: `pageSize` (10) with "Show more".
- **Bring your own data:** `balances` on TokenSelect and Portfolio, `transactions` on TransactionHistory, and `initialEvents` on EventFeed. Each skips the matching RPC reads.
- **Docs:** a new "Indexed data" guide recommends an index of the chain for production: your own Postgres (current state) + ClickHouse (history), or Goldsky (subgraphs, or Mirror into your own Postgres/ClickHouse). "In production" callouts on the relevant pages.

### Spam and prices (2026-10-13)

- **Prices by address:** `getTokenPrice(prices, token)` looks up `chainId:address`, then the address, then the symbol. Symbol keys priced copycats as the real token. Portfolio, Token Select, Token Input, Send and Swap all use it.
- **Portfolio spam filtering:**
  - Hidden reasons: `spam` (`isSpam`, default `looksLikeSpam`), `unpriced` (`hideUnpriced`, default on) and `dust` (`minValue`, default 0.5).
  - Hidden rows are left out of the total and collapsed under "Hidden tokens (N)" with the reason, so a false positive costs a click. Spam rows don't load the token's logo. The native currency is never hidden.
- **`looksLikeSpam`:** catches claim/airdrop text, links, domain symbols, invisible characters and lookalike letters. It flags 0 of the 1,598 EVM tokens on Uniswap's default list.
- **Scanner verdicts:** these go through `isSpam` from the app's server. The docs stay vendor-neutral.
- **Follow-ups:**
  - Extract the "Show more" button, which is now duplicated in Portfolio, TransactionHistory and TokenSelect.
  - ~~A `showUnlisted` mode for indexer data that carries its own token metadata.~~ Shipped 2026-11-18.

### Text morphing (2026-11-18)

- **`@0xui/morph-text`:** `MorphText` wraps `TextMorph` from [torph](https://github.com/lochie/torph). Text that changes in place morphs: shared characters slide, digits roll by place value.
- **Where:**
  - Button labels across phases: `transaction-button` (so also `approve-button`, `send`, `swap`), `batch-transaction`, `sign-message`, `add-token`, and the Read button in `contract-form`.
  - Live values: `block-number`, `gas-price`, the chain name in `chain-selector`, the rate and price impact in `swap`, the total in `portfolio`, the fiat line in `token-input`.
  - `token-amount` takes `animate` (off by default). `balance` turns it on. List rows in `portfolio` and `token-select` leave it off, since each instance measures and splits its text.
- **Not morphed:** status lines and alerts. They are sentences in live regions, and torph never wraps text.
- **jsdom:** torph throws without the Web Animations API, so `MorphText` renders a plain `span` there. Tests query labels as before, and never run the animation.
- **Children:** strings and numbers are joined into one label (`Approve {symbol}`). torph throws on a React element, so children that hold one render as-is.
- **Follow-ups:**
  - torph is `0.1.x`. Pin or re-check on upgrade.
  - It injects one `<style>` element, which a strict CSP blocks.

### Planned features (2026-11-18)

- **Mobile drawer:** `@0xui/responsive-dialog` is a dialog on larger screens and a bottom drawer below 640px. Rebuilt 2026-11-24 on the ui-sdk Dialog (`presentation="sheet"`); `auto` is now the sheet on small touch screens. The notes below describe the first version.
  - `connect-wallet` and `token-select` open it. Both take `mode` (`auto`, `dialog`, `drawer`).
  - Built on the shadcn `dialog` and `drawer` primitives, not ui-sdk: it sits under the flagship, and ui-sdk is still beta.
  - The drawer shows a swipe handle (`showSwipeHandle`, a Base UI drawer prop).
  - `chain-selector`'s dialog variant still opens a plain dialog.
- **Simulate gate:** `transaction-button` takes `simulate`.
  - It dry-runs the call from the connected account (`useSimulateContract`, or `useCall` for a plain transaction) once connected, on the right chain and with no `disabledReason`.
  - A revert disables the button ("Transaction will fail") and shows the contract's reason. It re-runs after each transaction.
  - `useTransactionSimulation` and `revertReason` are exported.
- **Switch account:** `account` lists the other connected wallets (`useConnections`) and switches with `useSwitchConnection`. Accounts inside one wallet are still switched in the wallet: wagmi has no API to pick one.

Components for private balances and transfers: shield, private send, unshield. Railgun first, Kohaku second. Step 1 (spike), step 2 (interface, mock, primitives) and step 3 (account and shield) are done. Steps 4 to 6 are planned. Everything shipped so far runs on the mock engine.

**Research findings (2026-11-18)**

_Railgun SDK_

- **Packages:** `@railgun-community/wallet` 11.3.5, `shared-models` 8.2.3, `engine` 9.9.1. All MIT, all CommonJS, all pinned to `ethers` 6.14.3. No viem.
- **Source moved:** the canonical repos are on `gitlab.com/railgun-protocol/community/*`. The GitHub `Railgun-Community` org is stale.
- **GPL underneath:** the engine depends on `@railgun-community/circomlibjs` (GPL-3.0) and needs `snarkjs` (GPL-3.0) as the prover.
- **Install today:** local npm has `min-release-age=7`, so use wallet 11.3.0 + shared-models 8.2.1 until the newer ones age in.
- **Browser needs:** an IndexedDB LevelDOWN store (`level-js`), your own `ArtifactStore`, Node polyfills (`crypto`, `stream`, `buffer`, `events`, `util`), and circuit artifacts fetched on demand (3–21 MB per circuit, 45 s timeout each).
- **No worker:** scanning and decryption run on the calling thread. The engine has to live in our own Web Worker.
- **Global state:** one callback slot per event and one cached proof. `populateProved*` throws unless it gets the exact arguments the proof was made with.
- **Proof progress is simulated** by a timer on the snarkjs path, so a real percentage does not exist.
- **Balance buckets:** `Spendable`, `ShieldPending`, `ProofSubmitted`, `MissingInternalPOI`, `MissingExternalPOI`, `ShieldBlocked`, `Spent`. Only `Spendable` can be spent.
- **Standby:** one hour on mainnet, 60 s on testnets. Blocked or pending shields can only go back to the address they came from ("unshield to origin").
- **Fees:** 25 bps to shield and 25 bps to unshield, read from the contract by `loadProvider`.
- **Public side:** the shield key is `keccak256(signMessage("RAILGUN_SHIELD"))`. Populate functions return an ethers transaction that maps onto wagmi `sendTransaction`.
- **Broadcasters:** `waku-broadcaster-client-web` 10.0.1 declares peer `wallet ~11.1.0`, which conflicts with 11.3.x. Self-broadcast needs no extra package but links the public address.
- **Networks:** Ethereum, BNB Chain, Polygon, Arbitrum, Base. Base has no classic RelayAdapt (EIP-7702 only). Sepolia has Proof of Innocence and is usable for demos; broadcasters there are unverified.
- **Successor:** "RAILGUN Reloaded" (`@railgun-reloaded/wallet-sdk`) is ESM, viem-native and worker-based, but marked WIP and not on npm.

_Kohaku (`ethereum/kohaku`)_

- **State:** alpha, "NOT READY FOR PRODUCTION USE… UNAUDITED CODE", several prereleases a week.
- **The Railgun plugin is a stub.** `packages/railgun` is a placeholder "to be reintroduced". The last usable build is npm `@kohaku-eth/railgun` 0.0.1-alpha.31, a Rust/WASM reimplementation pinned to old `plugins` and `provider` versions.
- **What works:** `@kohaku-eth/privacy-pools` (alpha.40 under the `alpha` tag) and `@kohaku-eth/tornado-cash`. Both do shield and unshield only, with no private transfer.
- **Plugin interface:** `prepareShield` / `prepareTransfer` / `prepareUnshield`, then `broadcast`. It has no sync events, proof stages, fee quotes, history or compliance states, and operation payloads are opaque per plugin.
- **Host assumes a wallet:** `Keystore.deriveAt(path)` returns a raw private key, which a wagmi-connected dapp cannot supply from the connected wallet.
- **Useful parts:** viem adapters (`@kohaku-eth/provider/viem`), the `AssetId` / `AssetAmount` shapes, and the `PluginError` classes.

_Prior art_

- **No React kit exists** for Railgun or Privacy Pools on npm. This is an open gap.
- **Reference apps are copyleft:** Railway Wallet (AGPL-3.0, the best reference), Faceless-Privacy (AGPL-3.0, wagmi + viem, closest to our stack), kohaku-extension (GPL-3.0), Privacy Pools site (CC BY-NC). Read them for flow and states, then write our own code and copy.
- **Mocking is normal:** Railway has `USE_FAKE_PROOF_IN_DEV`, and the Privacy Pools site swaps in wagmi's `mock` connector and skips proving.
- **Proof expiry:** Railway treats a broadcaster proof as valid for 240 s and locks the fee meanwhile. Changing the memo, signer or gas invalidates it.
- **Privacy pitfalls a UI can catch from local data:** unshielding to the address that shielded, matching amounts, exiting soon after entry, self-broadcast, public exits, a visible sender.
- **Request discipline:** queries keyed or enabled by user actions leak intent to the RPC, and so does polling a relayed transaction's hash.

**Decisions**

- **Own interface.** `shielded-engine` is a small 0xui interface. Kohaku's `PluginInstance` is not the contract, because it lacks sync, proof stages, fees and compliance states. We borrow its `prepare*` then `broadcast` split.
- **Three engines:**
  1. `mock-shielded-engine`: scripted sync, fake proof delay, bucket transitions. Every docs demo and test runs on it.
  2. `railgun-engine`: wraps `@railgun-community/wallet` inside a Web Worker. Ethers stays inside the adapter; components get `{ to, data, value }` and send through wagmi.
  3. `kohaku-engine` (experimental): Privacy Pools through `@kohaku-eth/privacy-pools`. Its job is to prove the interface fits a second protocol. Kohaku's Railgun plugin joins when it is reintroduced.
- **Account is a seed, not a signature.** The private account is a BIP-39 mnemonic encrypted with a password. It feeds both `createRailgunWallet` and Kohaku's `Keystore`. Components never hold the mnemonic; the engine does.
- **Neutral balance states,** mapped by each adapter:

  | 0xui state   | Railgun bucket                             | Privacy Pools            |
  | ------------ | ------------------------------------------ | ------------------------ |
  | `spendable`  | `Spendable`                                | approved                 |
  | `pending`    | `ShieldPending`                            | pending review           |
  | `proving`    | `ProofSubmitted`                           | none                     |
  | `incomplete` | `MissingInternalPOI`, `MissingExternalPOI` | none                     |
  | `restricted` | `ShieldBlocked`                            | declined, `poi_required` |

- **Proof progress shows stages** (`loading-circuits`, `proving`, `verifying`), not a percentage, since the percentage is fake.
- **Proofs expire.** A proved operation carries `expiresAt`, and any change to the draft sends the flow back to "ready to prove".
- **Self-broadcast first.** It needs no extra package and works on Sepolia. The broadcaster picker comes once the Waku client's peer range matches.
- **Capability flags per engine:** `transfer`, `relayer`, `viewOnly`, `exitToOrigin`, `memo`. Components hide what an engine cannot do.
- **Types only from Railgun.** Registry components use `import type` from `shared-models` at most, so they never pull in ethers or the engine.
- **CI:** engine adapters stay out of the "install every item" smoke job and get their own job.

**Spike results (2026-11-18)**

Step 1 ran as a Vite 8 app with the engine in a Web Worker, driven in headless Chrome against Sepolia. The verdict is **go** for Railgun in a worker. _Railgun, verified in the browser_

- **It bundles and runs in a worker.** wallet 11.3.0 + shared-models 8.2.1 + ethers 6.14.3 + snarkjs 0.7.6 + `level-js` + `localforage` (artifact store).
- **Vite config that works:**
  ```ts
  const polyfills = () => nodePolyfills({ globals: { Buffer: true, global: true, process: true } });
  export default defineConfig({
    define: { global: "globalThis" },
    plugins: [polyfills()],
    worker: { format: "es", plugins: () => [polyfills()] },
  });
  ```
- **The worker needs a shim as its first import.** `vite-plugin-node-polyfills` does not inject globals into worker bundles, and the worker died with `global is not defined` until `globalThis.global`, `Buffer` and `process` were set by hand.
- **The wallet's `postinstall` script** only patches React Native projects. Skipping it is fine.
- **Size:** the worker chunk is 9.87 MB (2.65 MB gzip), plus a 1.94 MB poseidon wasm (0.89 MB gzip). Circuit artifacts come on top, at proof time.
- **Timings:** engine start 0.7 s, `loadProvider` 0.7 s, `createRailgunWallet` 6.4 s, first balance scan 40.9 s.
- **No jank:** the longest main-thread frame gap during the scan was 17 ms.
- **Fees** came back as 25 and 25 bps. The `0zk` address is 127 characters.
- **Shield transaction:** `populateShieldBaseToken` took 8 ms and returned a call to the RelayAdapt contract with `value` equal to the amount and 868 bytes of data. It maps onto `sendTransaction` with no ethers on the page.
- **Scan progress is not monotonic.** There are two passes (UTXO, then TXID), each from 0 to 1. Progress jumped backwards (0.87 to 0.20), and the `Complete` event carries progress 0.
- **Balance events:** one event per bucket (seven per update), and the full set fired twice.
- **Scan errors on public RPCs:** "Failed to scan V2 events" twice and one "Invalid verification hash" on the TXID queue. The scan still finished.
- **The engine needs its own RPC URLs** (two providers, total weight at least 2) and a POI node URL. It cannot reuse the wagmi transport.

_Changes to the sketch, and why_

- **Listeners carry no payload.** An event says "this changed" and the state is read from the getters. The getters return the same reference until the state changes, so hooks use `useSyncExternalStore` and a component can never hold an event that disagrees with a getter. `ShieldedListener<E>` is gone.
- **`getSync(chainId)` is new.** A component that mounts mid-scan needs the current state, not the next event.
- **`getBalances` returns `undefined` until the first scan finishes.** An empty array means "scanned, holds nothing". The balance component needs the difference to show a skeleton.
- **`ShieldedBalance` became `ShieldedTokenBalance`.** The component is called `ShieldedBalance`. Amounts are a record with all five states, 0n when empty.
- **`sync(chainId)` is new.** It is the retry behind the sync error state and the "sync again" button. It resolves when the scan settles and never rejects; a failure shows up in `getSync`.
- **`retryProofs(chainId)` is new,** for `incomplete` funds. It is per chain, because the SDK call it maps to is per wallet and network.
- **An `account` event is new.** Components have to re-render on unlock and lock.
- **The `compliance` event is dropped.** The balance states already carry what a component shows.
- **Sync stages are `notes` and `transactions`,** neutral names for the UTXO pass and the TXID pass.
- **`PrivateDraft` has one member, `unshield`.** A proof needs a draft, and the only private operation the mock can show yet is an unshield. `transfer` joins in step 4.
- **Left out until a component uses them:** `capabilities`, `Submission`, `prepareShield`, `estimate`, `submit`, and typed error classes. Errors are plain `Error`s, and an aborted proof rejects with the signal's reason.
- **Kept though no component calls them yet:** `account.create` / `import` / `unlock` / `lock` (the mock implements them so step 3 has them), `id`, and `ProvedOperation.expiresAt`.

_Component decisions_

- **Token metadata is a prop.** `shielded-balance` takes `{ address, symbol, decimals }` and does not read them from the chain. An RPC lookup keyed by the tokens in a private balance would tell the RPC provider what the account holds.
- **`chainId` is a required prop** on `shielded-balance`, `shielded-sync-status` and their hooks (owner decision, 2026-11-18). The private balance lives on one chain whatever network the wallet is on, so the wagmi chain is the wrong default. No step 2 component needs a `WagmiProvider`. Later shielded components follow the same rule.
- **The bar is a pure function.** `advanceSync(previous, next)` spreads the stages evenly over 0 to 1 and keeps the highest value seen in a scan. A scan after a finished or failed one starts from 0. The stage order is a constant (`SHIELDED_SYNC_STAGES`), so an engine with one pass would jump from 50% to done.
- **Repeat scans are "updating".** Once balances exist, a scan reads "Updating private balance" with no step count, and `shielded-balance` sets `data-updating`. Otherwise the adapter's polling would replay the first-scan bar every interval.
- **`shielded-address` needs no engine.** It takes `address`, so it also shows recipients. The account's own address comes from `useShieldedAccount`.
- **`proof-progress` is controlled by props.** `useProof` wraps `engine.prove` and can be swapped for the step 4 flow hook. The phase while proving is the stage name.
- **`privacy-badge` is filled for private, outlined for public,** with different icons, so it does not depend on color. It uses theme variables only.
- **Default copy has no protocol words.** A test fails if "POI", "innocence", "Railgun" or "UTXO" appears in `shielded-balance`.
- **ui-sdk is not used.** No registry code uses it today; these follow the existing Base UI and shadcn pattern. (Superseded by the 2026-11-24 rebuild onto ui-sdk.)

_Mock_

- **Timings** (`MOCK_TIMINGS`, divided by `speed`): account creation 6 s, first scan 40 s, repeat scan 3.5 s, proof 13 s on the first run (4 s circuits, 8 s proving, 1 s verifying), standby 60 s. Three are guesses, not measurements: unlock 0.8 s, change settling 15 s, one proof retry 5 s.
- **The 6 s fee estimate is not in the mock,** because `estimate` is not in the interface yet.
- **`speed: Infinity` uses no timers.** Every flow finishes on the microtask queue, so a test can `await` each call. States that only last a while (`pending`) are tested with real delays and fake timers.
- **Balances change only when a scan finishes.** The mock keeps notes (what the account really holds) apart from the published snapshot. Every `simulate` call ends in a repeat scan.
- **`simulate` produces each state:** `shield` (fee, `pending`, then `spendable` or `restricted`), `unshield` (fee, whole notes spent, change `proving` then `spendable` or `incomplete`), `addFunds` (any state), `failNextSync`, `failNextProof`, `failNextRetry`, `keepIncomplete`.
- **Creating the engine starts no timers,** so it can be created during server render. Scanning starts on `unlock`, for the chains in `chains` (default `[1]`).
- **Proving moves no funds.** Without `submit`, a proved operation has nowhere to go; `simulate.unshield` stands in for it.

_Added to the interface_

```ts
export type ShieldDraft = { chainId: number; token: Address; amount: bigint };
export type ShieldQuote = { fee: bigint; received: bigint; standby: number }; // standby in seconds
export type PublicCall = { to: Address; data?: Hex; value?: bigint };
export type PreparedShield = { transaction: PublicCall; spender?: Address };
export type ShieldedTransaction = { kind: "shield"; token: Address; amount: bigint; state: ShieldedBalanceState };

// on ShieldedEngine
getTransaction(chainId: number, hash: Hash): ShieldedTransaction | undefined;
quoteShield(draft: ShieldDraft): Promise<ShieldQuote>;
prepareShield(draft: ShieldDraft, options: { sign(message: string): Promise<Hex> }): Promise<PreparedShield>;
```

_Changes to the sketch, and why_

- **`prepareShield` takes a `sign` callback.** Railgun derives the shield key from a wallet signature; other protocols need none. The engine calls `sign(message)` at most once, so the component never knows the message or whether one is needed. A rejected signature must reject with the wallet's error, which the block shows as a cancel.
- **`prepareShield` returns `{ transaction, spender }`, not `PublicCall[]`.** Same shape as a swap quote, so the existing `approve-button` does the allowance check, the USDT reset and the approval. The engine does not build approve calls.
- **`quoteShield` is new.** The fee, the amount received and the standby period have to be on screen before anything is signed. It maps to the fee read at `loadProvider` for Railgun and to `estimateShield` for Kohaku.
- **`getTransaction(chainId, hash)` is new.** It is what makes "a receipt is not proof" possible: it returns nothing until a scan has found the funds, then the state they are in. Changes ride on the `balances` event. The record has `kind: "shield"` only; step 4 adds the private kinds.
- **The order is sign, approve, send,** not approve, sign, send. The spender is only known once the engine has built the transaction, and the signature is free, so it goes first.

_`ShieldPhase` is smaller than planned_

```ts
export type ShieldPhase = "idle" | "preparing" | "signing" | "ready" | "cancelled" | "error";
export type ShieldedTxStatusPhase =
  | "pending"
  | "confirmed"
  | "standby"
  | "spendable"
  | "restricted"
  | "reverted"
  | "error";
```

The planned union ran from `idle` to `spendable` in one type. As built, each piece owns its own phases: the block covers what it does itself (building the transaction and the signature), the approve and send buttons keep `TxPhase`, and the status card covers everything after sending. One state machine per component, none duplicated.

_Component decisions_

- **The shield block first composed existing components** (`approve-button`, `transaction-button`). Replaced on 2026-11-19, see "Shield flow, as built".
- **Native currency is blocked** with "Wrap ETH to shield it". Open: a wrap step inside the block.
- **`shielded-transaction-status` nudges the engine.** When the public transaction is mined it calls `engine.sync(chainId)` once, since the engine does not know a shield was sent. After that it relies on the engine's own polling.
- **The countdown is an estimate.** It runs from the mined block's timestamp plus the quote's standby. The step completes only when the engine says `spendable`; past zero it reads "any moment now".
- **`shielded-account` holds the phrase only during backup.** `create` returns it, the hook keeps it until `confirmBackup`, then drops it. The words are not in the DOM until the user reveals them. `onUnlocked` and `children` wait for the backup step.
- **The import field** turns off spell check, autocomplete and autocapitalize, and opts out of password managers.
- **Password rule:** at least 8 characters, typed twice. No strength meter.
- **`shielded-account` renders nothing on the server,** so a locked account does not flash the create form while hydrating.
- **`address-input` validates `0zk` addresses by checksum.** Railgun addresses are bech32m with prefix `0zk` and 127 characters (confirmed in the engine source). The check is in `0xui-utils` (`isShieldedAddress`), tested against addresses from the engine's own test suite and the BIP-350 vectors. A private address is never sent to an ENS resolver. Without `shielded`, a pasted `0zk` address is turned down by name.
- **`transaction-status` now exports `StepIcon`,** reused by the new status card.

_Decisions after step 3 (owner, 2026-11-18)_

- **Batch approve and shield** in one wallet prompt with EIP-5792, only when the wallet reports atomic batching as `supported`. `ready` (the wallet would first upgrade the account) and `unsupported` fall back to separate prompts.
- **One click per wallet prompt.** No chained prompts from a single click: popup wallets need a user gesture for each. The one exception is a shield that takes exactly one prompt, where the form's button may open the wallet directly.
- **No shield key caching for now.** The signature is asked for on every shield. So a Railgun shield is two prompts on a batching wallet and three otherwise. Revisit in step 5, together with whether signatures from passkey and contract wallets repeat.
- **Built** in the `shield` block (2026-11-19): `useBatchedShield` sends the approval and the shield as one EIP-5792 batch when the wallet reports `supported` and the token needs an allowance. It approves the exact amount, clears a leftover allowance first, waits for the batch's call status, reads every receipt, and only then reports the shield's hash. `onSubmitted` therefore fires once the batch is mined. Other wallets keep `approve-button` in front of the shield button. Six tests cover it; the test wallet in `test/wagmi.tsx` takes `capabilities`.
- **`batch-transaction` still treats `ready` as atomic.** Only the shield block applies the stricter rule. Open: align the two.

_Shield flow, as built (2026-11-19)_

Four directions were prototyped behind a picker; the owner chose two, and both ship as variants of the block. The prototype is deleted.

- **One flow hook, two shells.** `useShieldFlow` runs the shield as a list of wallet steps (`sign`, `reset`, `approve`, `shield`, `batch`), one click each. `variant="in-place"` (default) locks the form and steps through the prompts on one button, then follows the shield in one line. `variant="collapse"` folds the form into a summary with a step list, then shows the status card until "Shield more".
- **The plan is known before the first prompt.** For that the quote grew two fields: `spender` (moved here from `PreparedShield`) and `needsSignature`. With the allowance and the wallet's capabilities they give the steps up front, so the form can say "Two wallet prompts: sign, approve and shield together."
- **The click that starts the shield opens the first prompt.** No extra click to leave the form, in either variant. After that, one click per prompt.
- **The draft is frozen at start,** with its quote. This replaces "a changed amount discards the built transaction": the amount can no longer change mid-flow.
- **The block sends the transactions itself** and no longer composes `approve-button` and `transaction-button`. It needed one stepper over all steps. `approve-button` now exports `requiresAllowanceReset`, so the USDT rule lives in one place.
- **`ShieldPhase` is now `idle | signing | approving | shielding | cancelled | error`.** `useShield` and `useBatchedShield` are gone; `useShieldFlow` covers both.
- **`shielded-transaction-status` has a `line` variant** and exports `shieldedStatusText`.
- **Mock:** `shieldSignature: false` imitates a protocol that needs no signature. With a batching wallet that is a single prompt, opened straight from the form.
- **Motion:** content swaps fade and rise over 200 ms, ease-out; the collapse variant animates its height; the summary amount shrinks from the input's size. All of it stops under reduced motion. It uses `tw-animate-css` classes, which shadcn installs.

**Risks**

- ~~The Railgun SDK may not bundle cleanly for a worker under Vite.~~ Settled by the spike: it does, with a polyfill plugin and a globals shim, and proofs generate inside the worker.
- Change stuck in `MissingExternalPOI` after a spend (seen on Sepolia). If this also happens on mainnet, every spend leaves funds unusable until it is solved.
- GPL-3.0 dependencies arrive in the user's app through `railgun-engine`. Registry source stays MIT, and the guide must say so.
- Kohaku is unaudited and changes weekly. `kohaku-engine` is labelled experimental and pins exact versions.
- A mnemonic in the browser is a real attack surface. The account component needs its own security review before release.

### Phase 6: Liquidity (LP) components (started 2026-11-21)
