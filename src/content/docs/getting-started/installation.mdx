0xui is a [shadcn registry](https://ui.shadcn.com/docs/registry). Components are copied into your project as source, so you own and can edit them.

## 1. Set up shadcn

If your project doesn't use shadcn yet, follow the [shadcn installation guide](https://ui.shadcn.com/docs/installation) for your framework. You need Tailwind CSS v4 and a `components.json`.

Either shadcn flavor works, Base UI or Radix. 0xui components don't use shadcn's `components/ui`: they bring their own primitives, built on [ui-sdk](https://ui-sdk.dev). shadcn is still needed for Tailwind, `cn` and the theme's CSS variables.

Put the ui-sdk layer at the very top of your global stylesheet, above `@import "tailwindcss"`, so your styles win over ui-sdk's:

```css title="globals.css" ins={1}
@layer ui-sdk;
@import "tailwindcss";
```

## 2. Add the 0xui registry

Add the `@0xui` namespace to `components.json`:

```json title="components.json" ins={3-5}
{
  // ...
  "registries": {
    "@0xui": "https://0xui.io/r/{name}.json"
  }
}
```

## 3. Add wagmi

<Install name="wagmi-config" />

This adds two files:

- `lib/wagmi-config.ts`: chains, connectors and transports. Edit it to match your app.
- `components/web3-provider.tsx`: `WagmiProvider` and a TanStack `QueryClientProvider`.

Paths follow the aliases in your `components.json`, so a Vite app gets `src/lib/wagmi-config.ts`.

Wrap your app once:

```tsx title="app.tsx"
import { Web3Provider } from "@/components/web3-provider";

export function App() {
  return <Web3Provider>{/* your app */}</Web3Provider>;
}
```

Optionally, register the config type so wagmi hooks infer your chain IDs:

```ts title="lib/wagmi-config.ts"
declare module "wagmi" {
  interface Register {
    config: typeof config;
  }
}
```

If you already have a wagmi setup, skip this step. Every 0xui component reads from whatever `WagmiProvider` is above it.

## 4. Add components

<Install name="chain-selector" />

Shared helpers (`@0xui/0xui-utils`, `@0xui/use-mounted`, …) and 0xui primitives (`@0xui/primitive-dialog`, `@0xui/primitive-popover`, …) install automatically as dependencies. Primitives land in `components/primitives/`.

### If the CLI asks to overwrite a file

A later install can ask to overwrite a file you never edited. In projects without React Server Components (Vite, for one), the shadcn CLI can add or drop the `"use client"` line depending on what else it installs, and that line is the whole difference. Answer either way: the install finishes and the component works.

Without a terminal (CI, a coding agent) the CLI can't ask. It stops there, exits with code 0 and leaves the install half done. Pass `--overwrite` to skip the question. It also replaces your own edits to any file the install touches, so check with `--dry-run` first if you have changed 0xui files.

## Using an AI agent

The shadcn MCP server lets agents browse and install from any registry in your `components.json`, including `@0xui`:

```bash
npx shadcn@latest mcp init
```
